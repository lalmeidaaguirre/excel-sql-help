The playbook

Excel and SQL, one task at a time

A working reference for the jobs that come up every week: looking things up, totaling by category, cleaning messy data, writing a query, joining tables, and checking that the numbers can be trusted. Every example is short enough to copy and adapt.

Part A

Excel essentials

Five skills that cover most of what analysts do in a spreadsheet.

A1

Look up a value from another table

You have a customer ID on one sheet and need the customer's name from another. That is a lookup. Use XLOOKUP if you have Excel 2021 or Microsoft 365, and VLOOKUP on older versions.

XLOOKUP 
=XLOOKUP(A2, Customers!A:A,
         Customers!B:B, "Not found")
VLOOKUP 
=VLOOKUP(A2, Customers!A:C, 2, FALSE)
  • XLOOKUP reads as: find this value, in this column, and return the match from that column. The last part is what to show when nothing matches.
  • With VLOOKUP, always end with FALSE for an exact match. Leaving it off can return a wrong row without any warning.
  • VLOOKUP can only look to the right of the lookup column. XLOOKUP can look in either direction.
A2

Total or count only the rows that match

To answer questions like "what were West region sales in 2026?" use the functions that end in IFS. They add or count only the rows that meet every condition you list.

Sum with conditions 
=SUMIFS(D2:D500,
        B2:B500, "West",
        C2:C500, 2026)
Count with conditions 
=COUNTIFS(B2:B500, "West",
          D2:D500, ">1000")

In SUMIFS the range to add comes first, followed by pairs: a range to test and the value it must equal. Comparisons such as ">1000" go inside quotation marks.

A3

Clean up messy text

Data pasted from other systems often carries stray spaces, odd capitalization, and numbers stored as text. These make lookups fail even when two values look identical.

ProblemFixWhat it does
Extra spaces=TRIM(A2)Removes leading, trailing, and doubled spaces
Hidden characters=CLEAN(A2)Strips non-printing characters
Inconsistent capitals=PROPER(A2)Capitalizes the first letter of each word
Numbers stored as text=VALUE(A2)Converts text that looks like a number into a number
Two values in one cellData, Text to ColumnsSplits a column at a comma, space, or other character

Clean into a new column, check the result, then copy and use Paste Special, Values to replace the original. That way a bad formula never destroys the source data.

A4

Summarize with a PivotTable

A PivotTable turns thousands of rows into a summary without a single formula. It is the fastest way to answer "how much, by what?"

  1. Click any cell inside your data. Make sure every column has a header and there are no blank rows.
  2. Go to Insert, PivotTable, and click OK to place it on a new sheet.
  3. Drag a category field, such as Region, into Rows.
  4. Drag a number field, such as Sales, into Values. Excel totals it by region.
  5. Drag a second field into Columns or Filters to slice the summary further.

If the source data changes, right-click the PivotTable and choose Refresh. It does not update on its own.

A5

Part B

SQL essentials

Enough SQL to pull, filter, combine, and summarize data on your own.

B1

Read a query from top to bottom

Almost every query uses the same clauses in the same order. Learn the order once and most "syntax error" messages go away.

The shape of a query 
SELECT   region, SUM(sales) AS total_sales   -- which columns to show
FROM     orders                              -- which table
WHERE    order_year = 2026                   -- which rows to keep
GROUP BY region                              -- how to group them
HAVING   SUM(sales) > 10000                  -- which groups to keep
ORDER BY total_sales DESC;                   -- how to sort the result

Only SELECT and FROM are required. Add the others as you need them, always in this order.

B2

Filter rows with WHERE

WHERE is the SQL version of an Excel filter. Combine conditions with AND and OR.

Common filters 
SELECT customer_id, last_name, state, balance
FROM   customers
WHERE  state IN ('TX', 'OK')            -- matches any value in the list
  AND  balance BETWEEN 100 AND 5000     -- a range, including both ends
  AND  last_name LIKE 'Mc%'             -- starts with Mc
  AND  email IS NOT NULL;               -- not blank
  • Text values go in single quotes. Numbers do not.
  • Use IS NULL to test for blanks. Writing = NULL never matches anything.
  • In LIKE, the percent sign stands for any number of characters.
B3

Join two tables

A join is a lookup for whole tables. It matches rows from two tables on a shared column, the way XLOOKUP matches on a lookup value.

Inner join: only matches 
SELECT o.order_id, c.last_name
FROM   orders o
JOIN   customers c
  ON   o.customer_id = c.customer_id;
Left join: keep every order 
SELECT o.order_id, c.last_name
FROM   orders o
LEFT JOIN customers c
  ON   o.customer_id = c.customer_id;
  • An inner join drops orders that have no matching customer. A left join keeps them and leaves the customer columns blank.
  • The letters o and c are aliases, short nicknames for the tables so you do not retype the full names.
  • If your row count jumps after a join, the column you joined on has duplicates in one of the tables.
B4

Summarize with GROUP BY

GROUP BY is the SQL version of a PivotTable. It collapses rows into one line per category and calculates a summary for each.

Sales by region 
SELECT   region,
         COUNT(*)   AS orders,
         SUM(sales) AS total_sales,
         AVG(sales) AS average_sale
FROM     orders
GROUP BY region
ORDER BY total_sales DESC;

The rule that trips people up: every column in SELECT must either be listed in GROUP BY or sit inside a summary function such as SUM or COUNT.

B5

Label rows with CASE

CASE does the job of Excel's IF. It checks conditions in order and returns the first one that is true.

Excel 
=IFS(D2 >= 5000, "Large",
     D2 >= 1000, "Medium",
     TRUE, "Small")
SQL 
SELECT order_id,
  CASE WHEN sales >= 5000 THEN 'Large'
       WHEN sales >= 1000 THEN 'Medium'
       ELSE 'Small'
  END AS order_size
FROM orders;

Part C

Validation checks

Run these before you report on any dataset. Each one shows the Excel way and the SQL way.

C1

Make a copy before you touch anything

Validation should never change the original. In Excel, save the workbook under a new name or duplicate the sheet and work there. In SQL, stick to SELECT statements while you investigate. They read data without changing it.

If a check turns up a problem, write down what you found and how many rows it affects before you fix anything. That note is what your manager or teammate will ask for.

C2

Look for duplicate records

A customer or invoice that appears twice gets counted twice. Check the column that is supposed to be unique, such as an ID or invoice number.

Excel 
=COUNTIF($A$2:$A$500, A2) > 1
SQL 
SELECT customer_id, COUNT(*) AS times_seen
FROM customers
GROUP BY customer_id
HAVING COUNT(*) > 1;
  • In Excel, put the formula in a helper column and fill it down. TRUE means the value appears more than once.
  • For a quick visual pass, select the column and use Home, Conditional Formatting, Highlight Cells Rules, Duplicate Values.
  • Only use Data, Remove Duplicates on your copy, and only after you know why the duplicates exist.
C3

Compare row counts

Count the rows in the source, then count them in your export or report. The two numbers should match. If they do not, records were dropped, filtered out, or multiplied by a join.

Excel 
=COUNTA(A2:A500)
SQL 
SELECT COUNT(*) AS row_count
FROM customers;

COUNT(*) counts every row in the table. COUNT(column) skips rows where that column is empty, so the two can give different answers. That difference is itself a useful clue.

C4

Tie out the totals

Two tables can have the same number of rows and still disagree. Add up a key amount on both sides, such as balance or sales, and compare.

Excel 
=SUM(D2:D500)
SQL 
SELECT SUM(balance) AS total_balance
FROM accounts;

If the totals are off, break the sum down by a category such as month or region. The group where the numbers stop matching tells you where to look.

C5

Hunt for blanks

Empty cells are easy to miss and they are skipped by sums, lookups, and joins. Count the blanks in every column your report depends on.

Excel 
=COUNTBLANK(A2:A500)
SQL 
SELECT COUNT(*) AS blank_rows
FROM customers
WHERE customer_id IS NULL;
C6

Find rows that are missing from the other table

When counts do not match, the next question is which records are missing. Look up every key from the first list in the second and keep the ones with no match.

Excel 
=IF(COUNTIF(Report!A:A, A2) = 0,
    "Missing", "")
SQL 
SELECT s.customer_id
FROM   source s
LEFT JOIN report r
  ON   s.customer_id = r.customer_id
WHERE  r.customer_id IS NULL;

Run it in both directions. Records can be missing from the report, and the report can also contain records that were never in the source.
